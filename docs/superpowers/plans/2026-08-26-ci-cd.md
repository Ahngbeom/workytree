# workytree CI/CD Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** PR/push마다 macOS·Linux에서 테스트+lint가 자동 실행되고, `v*.*.*` 태그 push가 버전 검증 후 GitHub Release를 만든다.

**Architecture:** GitHub Actions 워크플로 2개. `ci.yml`은 기존 `tests/run.zsh`와 `shellcheck`/`zsh -n`을 그대로 호출하고(별도 스크립트 없음), `install-smoke` job이 실제 `$HOME/.local` 경로로 `install.sh`를 end-to-end 검증한다. `release.yml`은 태그와 `bin/workytree`의 `WORKYTREE_VERSION` 일치를 검증한 뒤 `gh release create --generate-notes`로 릴리스를 만든다.

**Tech Stack:** GitHub Actions (`actions/checkout@v4`), zsh 5.9, shellcheck, `gh` CLI.

**Spec:** `docs/superpowers/specs/2026-08-26-ci-cd-design.md`

## Global Constraints

- 테스트 실행 명령은 로컬과 CI가 동일: `zsh tests/run.zsh`.
- 러너: `macos-latest`, `ubuntu-latest` 둘 다. ubuntu에는 `sudo apt-get install -y zsh`. **fzf는 설치하지 않는다.**
- `ci.yml`은 `permissions: contents: read`, `release.yml`만 `contents: write`.
- 릴리스 자산 첨부 없음. Homebrew/커버리지/release-please 범위 밖.
- 브랜치 보호는 코드가 아닌 GitHub 설정 — 사용자 확인 후 `gh api`로 적용.
- 커밋 메시지는 기존 규약(`feat:`/`fix:`/`chore:` 접두어) 사용. 커밋 메시지 끝에 `Co-Authored-By: Claude Fable 5 <noreply@anthropic.com>` 추가.

- [ ] **Step 5: `.github/workflows/ci.yml` 작성**

```yaml
name: ci

on:
  pull_request:
  push:
    branches: [main]

permissions:
  contents: read

concurrency:
  group: ci-${{ github.ref }}
  cancel-in-progress: true

jobs:
  test:
    name: test (${{ matrix.os }})
    runs-on: ${{ matrix.os }}
    timeout-minutes: 10
    strategy:
      fail-fast: false
      matrix:
        os: [macos-latest, ubuntu-latest]
    steps:
      - uses: actions/checkout@v4
      - name: Install zsh (Linux)
        if: runner.os == 'Linux'
        run: sudo apt-get update -q && sudo apt-get install -y -q zsh
      - name: Show tool versions
        run: zsh --version && git --version
      - name: Run tests
        run: zsh tests/run.zsh

  lint:
    runs-on: ubuntu-latest
    timeout-minutes: 5
    steps:
      - uses: actions/checkout@v4
      - name: Install zsh and shellcheck
        run: sudo apt-get update -q && sudo apt-get install -y -q zsh shellcheck
      - name: shellcheck install.sh
        run: shellcheck -s sh install.sh
      - name: zsh syntax check
        run: |
          rc=0
          for f in bin/workytree lib/*.zsh lib/cmd/*.zsh shell/workytree.zsh tests/*.zsh; do
            zsh -n "$f" || { echo "syntax error: $f"; rc=1; }
          done
          exit $rc
```

### Task 4: `release.yml` (태그 → 버전 검증 → GitHub Release)

**Files:**
- Create: `.github/workflows/release.yml`

**Interfaces:**
- Consumes: `bin/workytree:7` `typeset -g WORKYTREE_VERSION="0.1.0"` 형식(정확히 이 grep 패턴에 의존).
- Produces: `vX.Y.Z` 태그 push 시 Release. 태그·버전 불일치 시 실패.

- [ ] **Step 1: 버전 추출 명령을 로컬에서 확정**

Run: `sed -n 's/^typeset -g WORKYTREE_VERSION="\([^"]*\)".*/\1/p' bin/workytree`
Expected: `0.1.0`

- [ ] **Step 2: `.github/workflows/release.yml` 작성**

```yaml
name: release

on:
  push:
    tags: ['v*.*.*']

permissions:
  contents: write

jobs:
  release:
    runs-on: ubuntu-latest
    timeout-minutes: 10
    steps:
      - uses: actions/checkout@v4
      - name: Verify tag matches WORKYTREE_VERSION
        run: |
          tag="${GITHUB_REF_NAME#v}"
          ver="$(sed -n 's/^typeset -g WORKYTREE_VERSION="\([^"]*\)".*/\1/p' bin/workytree)"
          echo "tag=$tag version=$ver"
          if [ -z "$ver" ]; then echo "could not read WORKYTREE_VERSION from bin/workytree" >&2; exit 1; fi
          if [ "$tag" != "$ver" ]; then echo "tag v$tag does not match WORKYTREE_VERSION=$ver" >&2; exit 1; fi
      - name: Install zsh
        run: sudo apt-get update -q && sudo apt-get install -y -q zsh
      - name: Run tests
        run: zsh tests/run.zsh
      - name: Create GitHub Release
        env:
          GH_TOKEN: ${{ github.token }}
        run: gh release create "$GITHUB_REF_NAME" --title "$GITHUB_REF_NAME" --generate-notes
```

- [ ] **Step 3: 검증 step 로직을 로컬에서 불일치/일치 양쪽 테스트**

```bash
check() { tag="${1#v}"; ver="$(sed -n 's/^typeset -g WORKYTREE_VERSION="\([^"]*\)".*/\1/p' bin/workytree)"; [ "$tag" = "$ver" ]; echo "$1 -> rc=$?"; }
check v0.1.0; check v0.2.0
```
Expected: `v0.1.0 -> rc=0`, `v0.2.0 -> rc=1`

- [ ] **Step 4: YAML 검증, 커밋, push**

```bash
ruby -ryaml -e 'YAML.load_file(".github/workflows/release.yml"); puts "yaml ok"'
git add .github/workflows/release.yml
git commit -m "chore(ci): add tag-driven release workflow with version check"
git push
```
